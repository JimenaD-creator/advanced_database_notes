# Session – 2026-04-28

## Topics covered
- **Backups:** backups are basically copies of our database structure or data so we can restore everything if something breaks, gets deleted, or needs to be moved somewhere else. A backup can include just the schema (tables, views, constraints, etc.) or the actual data too.
- **SQL Engine:** is what processes SQL commands behind the scenes. It takes queries like SELECT, INSERT, UPDATE, or DELETE and figures out how to execute them correctly in the database.

## What I understood
- I understood that in Oracle, a schema is more like a user-owned collection of objects (tables, procedures, views), while the database is the full system that can contain many schemas. So a schema is just one part inside the larger database.
- I learned that DBMS_METADATA is useful when you only have SQL access because it can extract DDL for tables, views, sequences, and more.
- Schema backup means saving the structure only (CREATE TABLE, CREATE VIEW, etc.), while data backup means saving the actual records too, often through INSERT statements. Schema-only backup seemed easier because DBMS_METADATA can generate most of it automatically.
- I understood that restoring objects has to be done in the correct order because dependencies matter.

## What is still confusing
- I’m still a little confused about how to fully back up data without expdp, especially when generating INSERT statements manually.
- Foreign keys and dependency order make sense, but it can still get confusing when multiple objects depend on each other.
- The difference between some Oracle internal objects and user-created objects can also be unclear sometimes.

# Session – 2026-03-10

## Topics covered
During this session, we explored Set Operations. These operators allow us to combine the results of two or more independent queries into a single, unified result set. 

- UNION: Combines results and removes duplicates. It performs a distinct sort behind the scenes.

- UNION ALL: Combines results and keeps all duplicates. It is faster than UNION because it doesn't have to sort or filter.

- INTERSECT: Returns only the rows that exist in both query results.

- MINUS: Returns rows from the first query that are not present in the second query.

## What I understood
- UNION: If I have the same record in both tables, this operator merges them into one so I don't see the same data twice.

- UNION ALL: It just takes everything from Group A and everything from Group B and puts them together. It’s the fastest because the database doesn't waste time looking for duplicates.

- INTERSECT: This is how I find what two groups have in common. It only shows me the data that "lives" in both the first and second query.

- MINUS: This is a "Subtraction" logic. I take my first list and "cut out" anything that appears in the second list, leaving me only with what is unique to the first one.

- I learned that for any of these to work, the columns must mirror each other. They must have the same number of columns and the same data types in the exact same order.

- I realized that the column headers of the final result always come from the first SELECT statement, regardless of what the columns are named in the second one.

### Examples:
```sql
SELECT * FROM Books UNION SELECT * FROM Movies;
SELECT * FROM Books INTERSECT SELECT * FROM Movies;
SELECT * FROM Books MINUS SELECT * FROM Movies;
SELECT * FROM Books UNION ALL SELECT * FROM Movies;
```

# Session – 2026-04-07

## Topics covered
During this session, we covered Vector Search, a method that converts queries into numeric vectors. When a user makes a request, the system compares the query vector against those stored in the database to calculate mathematical similarity rather than searching for an exact text match.

- **Vector Search:** It is method that finds information by calculating the mathematical distance between a query and stored data in a multi-dimensional space. Unlike keyword search, it identifies results based on conceptual similarity, allowing it to find "near matches" even when exact words don't align.
- **Embedding Model:** It is a specialized neural network that converts text, images, or audio into long vectors. These models ensure that objects with similar meanings are assigned similar numerical coordinates, creating the foundation for computers to "understand" human context.
- **Semantic Search:** It is the process of breaking down large documents into smaller, meaningful pieces (chunks) based on their context or topic rather than just character counts. This ensures that the specific meaning of a paragraph is preserved so that the search system can retrieve precise answers instead of entire documents.

## What I understood
- We convert queries and documents into vectors using an Embedding Model. This model captures the meaning of words, placing conceptually similar items (like "King" and "Queen") close together in a high-dimensional space.
- Similarity is measured by the distance between vectors. Smaller distance = higher similarity. Common methods include Euclidean Distance (straight line) and Cosine Similarity (angle).
- Unlike traditional databases that look for exact matches, Vector Search looks for values that are "near" each other. This allows the system to find relevant results even if the user uses different words than the source text.

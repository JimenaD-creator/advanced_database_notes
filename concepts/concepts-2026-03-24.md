# Concept name
- Trigger
## My understanding
A trigger is like an automatic alarm for the data. It is a piece of code that stays "hidden" inside a table and waits for a specific action to happen, like an INSERT, UPDATE, or DELETE. The moment that action occurs, the trigger "wakes up" and runs its code automatically before the database finishes the task and without doing manually.

## Why it matters
It matters because it ensures that certain rules are followed every single time, no matter who is changing the data.

- It can stop a "bad" change before it happens (validation).
- It can automatically fix data (like making sure an email is always lowercase).
- It can keep a secret "history log" of every change made to a table so you can see who changed what and when.

## Example
Imagine a store database. We can create a trigger that says: "Whenever a new sale is INSERTED into the Sales table, automatically SUBTRACT that amount from the Inventory table". Because of the trigger, the employee doesn't have to remember to update the inventory manually; the database does it for them the instant the sale is recorded.
